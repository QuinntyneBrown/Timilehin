# L1 — High-Level Requirements

## L1-1: Responsive Layout System
The site shall provide fully responsive layouts for mobile (375px), tablet (768px), and desktop (1440px) screen sizes with consistent navigation and branding across all breakpoints.

## L1-2: Verse of the Day Module
The site shall display a prominent "Verse of the Day" section on the homepage that shows a daily Bible verse with its reference, styled for readability and visual appeal.

## L1-3: Bible Reader
The site shall provide a Bible reading interface where visitors can browse and read Bible verses by book, chapter, and verse, with a clean and readable typography layout. The layout shall match the ui-design.pen spacing (padding, margins, gaps, widths) at all three breakpoints (desktop 1440px, tablet 768px, mobile 375px). The design shall reference integration with a free Bible API (bible-api.com or API.Bible).

## L1-4: Devotionals Section
The site shall include an integrated devotionals area on the frontend where users can read daily devotional content, including a title, scripture reference, reflection text, and prayer prompt. The page shall have proper padding and margins at all three breakpoints (desktop 1440px, tablet 768px, mobile 375px).

## L1-5: Homepage & Navigation
The site shall have a cohesive homepage that ties together the Verse of the Day, Bible Reader access, and Devotionals with clear navigation and a visually engaging hero section.

## L1-6: Backend API — Verse of the Day
The backend shall expose a REST API endpoint that returns the daily Bible verse by proxying bible-api.com, with server-side caching to avoid redundant external calls.

## L1-7: Backend API — Bible Reader
The backend shall expose REST API endpoints that proxy bible-api.com to provide Bible chapter content with verse-level data, allowing the frontend to read any book and chapter.

## L1-8: Backend API — Devotionals
The backend shall expose REST API endpoints for full CRUD management of devotional content, with pagination for listing, a "today" endpoint, and persistent storage via SQLite and Entity Framework Core.

## L1-9: Backend Infrastructure
The backend shall be built as an ASP.NET Core Web API with proper service abstractions, CORS configuration, OpenAPI documentation, and automated database provisioning on startup.

## L1-10: Domain Smart Components
The Angular `domain` library shall provide smart (container) components that wire the `api` library services to the `components` library presentational components. These domain components manage data fetching, loading/error state, and user interaction for each page of the application: Homepage, Bible Reader, and Devotionals.

## L1-11: Frontend App Implementation
The Angular application in `projects/timilehin` shall implement the ui-design.pen screens by wiring up routing, page-level components, global styles, and HTTP configuration. The app shall use domain containers for smart logic, the components library for presentation, and the api library for backend communication via a development proxy.

## L1-12: End-to-End Playwright Tests
The project shall include Playwright end-to-end tests using the actual backend API (src/Timilehin.Api) with a Page Object Model pattern. Tests shall cover all user flows: homepage navigation, Bible reading, and devotional browsing.

## L1-13: UI Design Verification Tests
Playwright tests shall verify that the ui-design.pen was implemented correctly by checking typography (font families, font sizes), spacing (padding, margins, gaps), colors, and layout structure across all pages and breakpoints (desktop 1440px, tablet 768px, mobile 375px).
