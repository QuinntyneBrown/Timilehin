## L1-1: Responsive Layout System

### L2-1.1: Mobile Layout (375px)
**Traces to:** L1-1

**Traces to:** L1-1
Two-column grid where appropriate, with visible navigation links and balanced spacing.
**Acceptance Criteria:**
- Tablet frame is 768px wide
- Navigation shows key links inline
- Content uses 2-column grid where suitable
- Proper padding and margins for tablet reading

### L2-1.3: Desktop Layout (1440px)
**Traces to:** L1-1
Full-width layout with horizontal navigation bar, multi-column content areas, and sidebar where appropriate.
**Acceptance Criteria:**
- Desktop frame is 1440px wide
- Full horizontal navigation with all links visible
- Hero section spans full width
- Content areas use up to 3 columns where appropriate

## L1-6: Backend API — Verse of the Day

### L2-6.1: Verse of the Day Endpoint
**Traces to:** L1-6
A GET endpoint at `/api/verseoftheday` that returns today's Bible verse reference and text.
**Acceptance Criteria:**
- GET `/api/verseoftheday` returns 200 with JSON containing `reference` and `text` fields
- The verse rotates daily based on a curated list of popular Bible verses
- Response is cached in the database per day to avoid repeat external API calls
- If the external API call fails, the endpoint returns a graceful fallback response (not 500)

### L2-6.2: Verse of the Day Caching
**Traces to:** L1-6
The VerseOfTheDay entity is persisted in SQLite with a unique date index, so each day's verse is fetched from bible-api.com at most once.
**Acceptance Criteria:**
- A `VerseOfTheDay` model exists with `Id`, `Date`, `Reference`, and `Text` properties
- The `Date` column has a unique index
- On first request of the day, the verse is fetched from bible-api.com and stored
- Subsequent requests on the same day return the cached database record

## L1-7: Backend API — Bible Reader

### L2-7.1: Bible Chapter Endpoint
**Traces to:** L1-7
A GET endpoint at `/api/bible/{book}/{chapter}` that returns all verses for the given book and chapter.
**Acceptance Criteria:**
- GET `/api/bible/Genesis/1` returns 200 with JSON containing `reference`, `verses` array, and `translation`
- Each verse object contains `verse` (number) and `text` (string)
- Returns 404 with a descriptive message for invalid book/chapter combinations
- The `book` parameter supports multi-word book names (e.g., `1 Corinthians`)

## L1-8: Backend API — Devotionals

### L2-8.1: Devotional List Endpoint
**Traces to:** L1-8
A GET endpoint at `/api/devotionals` that returns a paginated list of devotional summaries.
**Acceptance Criteria:**
- GET `/api/devotionals` returns 200 with paginated results
- Supports `page` and `pageSize` query parameters (defaults: page=1, pageSize=10)
- Results are ordered by date descending (newest first)
- Each item includes `id`, `title`, `date`, `scriptureReference`, and a truncated `excerpt` (max 150 chars)
- Response includes `totalCount`, `page`, `pageSize`, `totalPages`, `hasNextPage`, `hasPreviousPage`

### L2-8.2: Devotional Detail Endpoint
**Traces to:** L1-8
A GET endpoint at `/api/devotionals/{id}` that returns the full devotional content.
**Acceptance Criteria:**
- GET `/api/devotionals/1` returns 200 with full devotional including `reflectionText` and `prayerPrompt`
- Returns 404 for non-existent IDs

### L2-8.3: Today's Devotional Endpoint
**Traces to:** L1-8
A GET endpoint at `/api/devotionals/today` that returns the devotional matching today's date.
**Acceptance Criteria:**
- GET `/api/devotionals/today` returns 200 with today's devotional if one exists
- Returns 404 with descriptive message if no devotional exists for today

### L2-8.4: Create Devotional Endpoint
**Traces to:** L1-8
A POST endpoint at `/api/devotionals` that creates a new devotional entry.
**Acceptance Criteria:**
- POST `/api/devotionals` with valid JSON body returns 201 with the created resource
- Response includes a `Location` header pointing to the new resource
- Request body requires `title`, `date`, `scriptureReference`, `reflectionText`, `prayerPrompt`

### L2-8.5: Update Devotional Endpoint
**Traces to:** L1-8
A PUT endpoint at `/api/devotionals/{id}` that partially updates an existing devotional.
**Acceptance Criteria:**
- PUT `/api/devotionals/1` with partial JSON body returns 200 with the updated resource
- Only provided fields are updated; omitted fields remain unchanged
- Returns 404 for non-existent IDs

### L2-8.6: Delete Devotional Endpoint
**Traces to:** L1-8
A DELETE endpoint at `/api/devotionals/{id}` that removes a devotional.
**Acceptance Criteria:**
- DELETE `/api/devotionals/1` returns 204 No Content on success
- Returns 404 for non-existent IDs

## L1-9: Backend Infrastructure

### L2-9.1: EF Core DbContext and Database
**Traces to:** L1-9
An `AppDbContext` with DbSets for `Devotional` and `VerseOfTheDay`, configured with SQLite and auto-created on startup.
**Acceptance Criteria:**
- `AppDbContext` contains `DbSet<Devotional>` and `DbSet<VerseOfTheDay>`
- Database is created automatically via `EnsureCreatedAsync` on application startup
- Connection string is configured in `appsettings.json`

### L2-9.2: Service Layer Abstractions
**Traces to:** L1-9
All business logic is encapsulated behind `IBibleService` and `IDevotionalService` interfaces, registered via dependency injection.
**Acceptance Criteria:**
- `IBibleService` declares `GetVerseOfTheDayAsync` and `GetChapterAsync` methods
- `IDevotionalService` declares `GetAllAsync`, `GetByIdAsync`, `GetTodayAsync`, `CreateAsync`, `UpdateAsync`, `DeleteAsync` methods
- Services are registered in DI container with appropriate lifetimes
- `BibleApiService` uses `HttpClient` via `IHttpClientFactory` pattern

### L2-9.3: CORS Configuration
**Traces to:** L1-9
The API is configured with a CORS policy that allows the frontend origins.
**Acceptance Criteria:**
- CORS allows origins configured in `appsettings.json` under `Cors:Origins`
- Defaults to `http://localhost:3000` if no configuration is provided
- Allows any header and any method

### L2-9.4: OpenAPI Documentation
**Traces to:** L1-9
The API exposes an OpenAPI specification in development mode.
**Acceptance Criteria:**
- OpenAPI endpoint is mapped when running in Development environment
- All API endpoints are discoverable via the OpenAPI spec
